# データベース移行仕様

**対象フィーチャー:** `lib/features/alarm/`
**作成日:** 2026-05-27
**ステータス:** 策定中

**関連ドキュメント:**
- [RAGシステム導入 変更仕様書](rag_system_spec.md) — 本ドキュメントは RAG 仕様書の Phase 0・Phase 4 を詳細化したもの

---

## 1. 目的

alarm フィーチャーの睡眠データ保存先を **SharedPreferences（JSON）から SQLite に移行する**。

移行の主な理由は以下の通り。

- `sleep_epochs`（加速度センサーの時系列データ）が増加するにつれ、SharedPreferences では全件を一括でメモリに展開するため非効率になる
- SQLite にすることで期間指定・セッション単位の絞り込みクエリが可能になり、RAG システムへのデータ供給が容易になる
- `sqflite` パッケージは既に依存関係に含まれており、追加ライブラリは不要

---

## 2. 現状のデータ構造（SharedPreferences）

| キー | 内容 |
|---|---|
| `sleep_sessions` | セッション一覧（JSON 配列） |
| `sleep_epochs` | 加速度センサーの時系列データ（JSON 配列） |
| `sleep_notes` | ライフスタイル記録（JSON 配列） |

### 各モデルの主要フィールド

**SleepSession**

| フィールド | 型 | 内容 |
|---|---|---|
| `id` | String | セッション ID（`session_${timestamp}` 形式） |
| `startAtEpochMs` | int | 就寝時刻（ms） |
| `endAtEpochMs` | int? | 起床時刻（ms） |
| `alarmTimeEpochMs` | int? | アラーム設定時刻（ms） |
| `status` | String | `recording` / `finished` |
| `algoVersion` | String | アルゴリズムバージョン（例: `wave_v1`） |
| `samplingPeriodSec` | int | サンプリング間隔（秒） |
| `tzOffsetMin` | int | タイムゾーンオフセット（分） |
| `appVersion` | String | アプリバージョン |
| `syncState` | String | 同期状態（例: `local_only`） |

**SleepEpoch**

| フィールド | 型 | 内容 |
|---|---|---|
| `sessionId` | String | 対応セッションの ID |
| `tEpochMs` | int | 計測時刻（ms） |
| `activityCount` | double | 体動量 0.0〜1.0（加速度センサー由来） |
| `scoreDepth` | double | 睡眠深度スコア 0.0〜1.0（activityCount から算出） |

**SleepNote**

| フィールド | 型 | 内容 |
|---|---|---|
| `sessionId` | String | 対応セッションの ID |
| `createdAtEpochMs` | int | 記録時刻（ms） |
| `memo` | String | ユーザーメモ |
| `hadAlcohol` | bool | 飲酒の有無 |
| `hadCaffeine` | bool | カフェイン摂取の有無 |
| `didExercise` | bool | 運動の有無 |

## 3. SQLite テーブル定義

```sql
CREATE TABLE sleep_sessions (
    id                TEXT    PRIMARY KEY,
    startAtEpochMs    INTEGER NOT NULL,
    endAtEpochMs      INTEGER,
    alarmTimeEpochMs  INTEGER,
    status            TEXT    NOT NULL,
    algoVersion       TEXT    NOT NULL,
    samplingPeriodSec INTEGER NOT NULL,
    tzOffsetMin       INTEGER NOT NULL,
    appVersion        TEXT    NOT NULL,
    syncState         TEXT    NOT NULL
);

-- 加速度センサーの時系列データ（1セッションあたり60〜180件程度）
CREATE TABLE sleep_epochs (
    sessionId     TEXT    NOT NULL,
    tEpochMs      INTEGER NOT NULL,
    activityCount REAL    NOT NULL,
    scoreDepth    REAL    NOT NULL,
    PRIMARY KEY (sessionId, tEpochMs),
    FOREIGN KEY (sessionId) REFERENCES sleep_sessions(id)
);

CREATE TABLE sleep_notes (
    sessionId        TEXT    PRIMARY KEY,
    createdAtEpochMs INTEGER NOT NULL,
    memo             TEXT    NOT NULL,
    hadAlcohol       INTEGER NOT NULL,   -- 0 / 1
    hadCaffeine      INTEGER NOT NULL,
    didExercise      INTEGER NOT NULL,
    FOREIGN KEY (sessionId) REFERENCES sleep_sessions(id)
);
```

## 4. 新設ファイル一覧

```
features/alarm/infrastructure/
  db/
    sleep_database.dart              # DB初期化・テーブル作成・バージョン管理
    sleep_sqlite_repository.dart     # SQLite実装（既存インターフェースを実装）
  migration/
    shared_prefs_to_sqlite.dart      # 既存データの一回限りの移行処理
```

### sleep_database.dart

- DB ファイル名・バージョンを定数として管理
- `onCreate` で 3 テーブルを作成
- `onUpgrade` でスキーマ変更に対応（将来の拡張用）

### sleep_sqlite_repository.dart

既存の `SleepRepository` インターフェースをそのまま SQLite で再実装する。
インターフェースは変えないため、上位レイヤー（記録処理・グラフ表示）への影響は最小限。

**Phase 0 で実装するメソッド（読み取りのみ）**

```dart
Future<List<SleepSession>> getSessions();
Future<List<SleepEpoch>>   getEpochsBySessionId(String sessionId);
Future<SleepNote?>         getNotesBySessionId(String sessionId);
```

**Phase 4 で追加するメソッド（書き込み）**

```dart
Future<void> saveSession(SleepSession session);
Future<void> saveEpochs(List<SleepEpoch> epochs);
Future<void> saveNote(SleepNote note);
Future<void> removeSession(String sessionId);
Future<void> clearAll();
```

### shared_prefs_to_sqlite.dart

アプリ起動時に一度だけ実行する移行処理。

```
1. SharedPreferences に移行済みフラグ（sqlite_migrated）があるか確認
2. フラグがなければ SharedPreferences から全データを読み取り
3. SQLite の各テーブルに INSERT
4. 移行済みフラグを書き込み（以降はスキップ）
```

## 6. ダミーデータ仕様（Phase 0 用）

RAG 開発を先行するために、Phase 0 で SQLite にダミーデータを投入する。

### データ量

| テーブル | レコード数 |
|---|---|
| sleep_sessions | 7件（直近1週間分） |
| sleep_epochs | 各セッション 84件（7時間 × 12件/時） |
| sleep_notes | 7件（各セッションに1件） |

### ダミーデータの特徴

- `activityCount` はサイン波ベースのパターン（`algoVersion: wave_v1`）
- 睡眠深度スコアの変換ルール：
  - activityCount ≥ 0.8 → scoreDepth = 0.2（浅い）
  - activityCount ≥ 0.5 → scoreDepth = 0.5
  - activityCount ≥ 0.2 → scoreDepth = 0.8
  - activityCount < 0.2 → scoreDepth = 1.0（深い）
- ライフスタイル記録はバリエーションをもたせる（飲酒あり・なし、運動あり・なし等）

### 配置場所

```
smfb_app/
  lib/
    data/
      products/   # 商品PDF（RAGの商品参照の一次ソース）
  data/
    sleep/       # 開発用ダミー睡眠データ（SQLite .db ファイル等）
    index/       # 商品PDFから生成する検索インデックス（必要な場合のみ、.gitignore 対象）
```

`.gitignore` の設定：
- `data/index/` — 商品PDFから生成する検索インデックスは再生成可能なため除外
- `data/sleep/*.db` — 実データの SQLite ファイルは個人情報を含むため除外
- `data/products/*.pdf` — 商品データの一次ソース。管理対象にするかはPDFの権利・容量を確認して決める

### 投入方法

アプリ起動時に DB が空の場合のみダミーデータを挿入する処理を `sleep_database.dart` に組み込む（Phase 4 で実データに切り替えた後は削除）。

## 7. 作業フェーズ

| フェーズ | 内容 | 前提 |
|---|---|---|
| **Phase 0** | SQLite DB 初期化・読み取りメソッド実装・ダミーデータ投入 | なし |
| **Phase 4** | 書き込みメソッド実装・マイグレーション・グラフ参照先変更 | Phase 3（RAG完成）後 |

Phase 0〜3 の間、alarm フィーチャーの **書き込み処理は SharedPreferences のまま**維持する。
既存の記録・グラフ機能には一切触れない。
