# 睡眠データ保存形式と画面参照 現状

作成日: 2026-05-29

対象:

- `lib/db/`
- `lib/features/alarm/`
- `lib/features/graph/`
- `lib/features/fb/`

## 結論

現在の睡眠データは、Androidなどの非Web環境ではSQLiteへ保存されます。
Chrome/WebではSQLiteを使わず、従来通りSharedPreferencesへ保存します。

グラフ画面とFB画面は、現時点ではSQLiteを直接参照していません。
どちらも `SleepRepository.instance` のメモリキャッシュを参照します。

非Web環境では、アプリ起動時に `SleepRepository` がSQLiteからデータを読み込み、その内容をメモリキャッシュへ展開します。
そのため、グラフやFBは「SQLiteから読み込まれたキャッシュ」を見る構成です。

## 保存先

### SQLite

DB初期化:

- `lib/db/sleep_database.dart`

SQLite保存・取得:

- `lib/features/alarm/infrastructure/sleep_sqlite_repository.dart`

DBファイル名:

- `sleep_data.db`

Androidエミュレータ/実機での実体:

```text
/data/data/com.example.smf_app/databases/sleep_data.db
```

開発確認用コピー:

```text
lib/db/sleep_data_dev.db
```

注意:

- `lib/db/sleep_data_dev.db` はエミュレータ内DBのコピーです。
- アプリが直接読み書きしているDB本体ではありません。
- アプリでデータを追加した場合、必要に応じて再コピーが必要です。

再コピー用スクリプト:

```powershell
powershell -ExecutionPolicy Bypass -File tools/sync_sleep_db.ps1
```

自動同期する場合:

```powershell
powershell -ExecutionPolicy Bypass -File tools/sync_sleep_db.ps1 -Watch
```

`-Watch` を付けると、既定では3秒ごとにエミュレータ内の `sleep_data.db` を `lib/db/sleep_data_dev.db` へコピーします。
これにより、IDE上で確認するDBコピーをほぼ最新の状態に保てます。

### SharedPreferences

互換用・Web用の保存先です。

管理ファイル:

- `lib/features/alarm/infrastructure/sleep_repository.dart`

キー:

```text
sleep_sessions
sleep_epochs
sleep_notes
```

形式:

- `StringList`
- 各要素は `toJson()` の結果を `jsonEncode()` した文字列

Androidでの実体はアプリ専用領域のSharedPreferencesです。
プロジェクトファイル内には直接保存されません。

## SQLiteテーブル

### sleep_sessions

睡眠1回分の親データです。

主なカラム:

```text
id TEXT PRIMARY KEY
startAtEpochMs INTEGER NOT NULL
endAtEpochMs INTEGER
alarmTimeEpochMs INTEGER
status TEXT NOT NULL
algoVersion TEXT NOT NULL
samplingPeriodSec INTEGER NOT NULL
tzOffsetMin INTEGER NOT NULL
appVersion TEXT NOT NULL
syncState TEXT NOT NULL
```

対応モデル:

- `SleepSession`

### sleep_epochs

睡眠中の時系列データです。

主なカラム:

```text
sessionId TEXT NOT NULL
tEpochMs INTEGER NOT NULL
activityCount REAL NOT NULL
scoreDepth REAL NOT NULL
PRIMARY KEY (sessionId, tEpochMs)
```

対応モデル:

- `SleepEpoch`

### sleep_notes

メモと生活行動フラグです。

主なカラム:

```text
sessionId TEXT PRIMARY KEY
createdAtEpochMs INTEGER NOT NULL
memo TEXT NOT NULL
hadAlcohol INTEGER NOT NULL
hadCaffeine INTEGER NOT NULL
didExercise INTEGER NOT NULL
```

対応モデル:

- `SleepNote`

## ダミーデータ

作成ファイル:

- `lib/features/alarm/application/dummy_sleep_data_service.dart`

保存されるデータ:

- `SleepSession`
- `SleepEpoch` 一覧
- `SleepNote`

ID形式:

```text
dummy_yyyymmdd
```

特徴:

- `algoVersion` は `wave_v1`
- `SleepEpoch` はサイン波ベースで生成
- `memo` は `Demo用ダミーデータ（サイン波生成）`
- `hadAlcohol` / `hadCaffeine` / `didExercise` はランダム

保存経路:

```text
DummySleepDataService.generateAndSave()
  -> SleepRepository.saveSession()
  -> SleepRepository.removeEpochsForSession()
  -> SleepRepository.saveEpochs()
  -> SleepRepository.saveNote()
```

非Web環境では、この経路でSQLiteにも保存されます。

## 実データ

作成ファイル:

- `lib/features/alarm/application/sleep_recorder_service.dart`
- `lib/features/alarm/presentation/alarm_page.dart`

保存されるデータ:

- STOP時に `SleepSession`
- STOP時に `SleepEpoch` 一覧
- メモ保存時に `SleepNote`

保存経路:

```text
AlarmPage._stopRecording()
  -> SleepRepository.saveSession(result.session)
  -> SleepRepository.saveEpochs(result.epochs)

_MemoDialog
  -> SleepRepository.saveNote()
```

非Web環境では、この経路でSQLiteにも保存されます。

注意:

- 現在の実データの `SleepEpoch.activityCount` は加速度センサー由来ではありません。
- `SleepRecorderService` の `_mockActivityCount()` による仮データです。
- 加速度センサー連携は未実装です。

## 環境別の保存対応

| 環境 | SQLite保存 | SharedPreferences保存 | 備考 |
| --- | --- | --- | --- |
| Androidエミュレータ/実機 | 対応 | 対応 | 現在の主な検証環境 |
| Windowsデスクトップ | 対応予定 | 対応 | Visual Studio C++ toolchainが必要 |
| Chrome/Web | 非対応 | 対応 | SQLiteは使わない |

## グラフ画面の参照先

対象ファイル:

- `lib/features/graph/presentation/graph_page.dart`

参照しているもの:

```text
SleepRepository.instance.allSessions
SleepRepository.instance.epochsForSession(session.id)
SleepRepository.instance.notesForSession(session.id)
```

現状:

- SQLiteを直接参照していません。
- `SleepRepository` のメモリキャッシュを参照しています。
- 非Web環境では、起動時にSQLiteから読み込まれた内容がメモリキャッシュに入ります。

補足:

- グラフ画面の行動選択 `action_selections` は、現時点ではSharedPreferencesに保存されています。
- `食事`、`喫煙`、`入浴` などはSQLiteの `sleep_notes` には入りません。

## FB画面の参照先

対象ファイル:

- `lib/features/fb/presentation/pages/fb_dashboard_page.dart`

参照しているもの:

```text
SleepRepository.instance.allSessions
SleepRepository.instance.notesForSession(session.id)
```

現状:

- SQLiteを直接参照していません。
- `SleepRepository` のメモリキャッシュを参照しています。
- 現在の通常FBプロンプトで使う睡眠情報は、主にセッション情報とメモです。
- `SleepEpoch` の `activityCount` / `scoreDepth` は、現時点のFBプロンプトでは使っていません。

FB関連のAIキャッシュ:

```text
fb_ai_advice_<sessionId>
fb_special_<type>_<sessionId>
fb_chat_history_<sessionId>
```

これらは現時点ではSharedPreferencesに保存されています。
SQLiteには保存していません。

## RAG向けの現状

RAGで使える土台:

- SQLiteに `sleep_sessions` / `sleep_epochs` / `sleep_notes` が保存される
- `sleep_sqlite_repository.dart` からSQLiteデータを読み出せる
- 開発確認用に `lib/db/sleep_data_dev.db` を作成できる

まだ未対応のこと:

- FB/RAG入力用の専用payload作成
- `SleepEpoch` の要約
- 直近1件/直近7日などの抽出条件
- Pythonバックエンドへの送信
- AIキャッシュやチャット履歴のSQLite移行
